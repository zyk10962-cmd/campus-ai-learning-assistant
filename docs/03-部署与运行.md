# 部署与运行

本项目完全本地运行：Dify 用 Docker 部署，模型用 Ollama 跑在本机。

## 一、环境要求

| 组件 | 说明 |
|---|---|
| Docker Desktop | 运行 Dify 的容器组 |
| Ollama | 本地模型运行服务 |
| Qwen3:8b | 对话模型，约 5 GB |
| BGE-M3 | 向量模型，约 1.2 GB |

建议内存 16 GB 以上；纯 CPU 也能跑，但首次生成会明显变慢。

## 二、拉取模型

```bash
ollama pull qwen3:8b
ollama pull bge-m3
```

拉完后确认一下：

```bash
ollama list
```

能看到 `qwen3:8b` 和 `bge-m3` 两行即可。

## 三、启动 Dify

1. 克隆官方仓库：

```bash
git clone https://github.com/langgenius/dify.git
cd dify/docker
```

2. 复制环境变量模板（这一步生成的文件含数据库密码，不要提交到 Git）：

```bash
cp .env.example .env
```

3. 启动容器：

```bash
docker compose up -d
```

4. 浏览器访问 `http://localhost`，首次进入需要设置管理员账号。

## 四、接入 Ollama

在 Dify 里进入「设置 → 模型供应商 → Ollama」，填写：

- Base URL：`http://host.docker.internal:11434`
  （Docker 容器访问宿主机上的 Ollama 用这个地址；Linux 下可改为宿主机 IP）
- 模型名称：`qwen3:8b`

保存后可在模型列表里看到该模型。

## 五、创建知识库

1. 进入「知识库 → 创建知识库」，上传 `knowledge_base/校园事务测试资料.txt`。
2. 分段设置保持默认即可（该文档只有三个小节，按段落切分效果稳定）。
3. 索引方式选择「高质量」，嵌入模型选择 **BGE-M3**。
4. 等待索引完成后，在知识库中测试检索「请假」「奖学金」，能命中对应段落即可。

## 六、搭建 Chatflow

按 [02-工作流设计.md](02-工作流设计.md) 的结构创建应用：

1. 新建应用，类型选择 **Chatflow**。
2. 依次添加开始节点、问题分类器、知识检索、LLM、变量赋值、直接回复等节点。
3. 问题分类器设置两个类别：`新问题`、`提交答案`。
4. 知识检索节点选中刚创建的知识库；LLM 节点选择 `qwen3:8b`。
5. 变量赋值节点把 `correct_answers` 写入会话变量。
6. 逐个节点连线后，用右侧「预览」调试。

## 七、验证流程

在预览或已发布的聊天页面中：

1. 输入「请假需要准备哪些材料」→ 应返回回答、知识点总结和一道选择题，下方有引用。
2. 输入选项字母（如 `a`）→ 应返回批改结果、得分和解析。
3. 输入知识库没有的问题（如「食堂几点开门」）→ 应提示咨询相关部门，而不是编造答案。

## 八、常见问题

| 现象 | 排查方向 |
|---|---|
| Dify 里连不上 Ollama | 确认 Ollama 正在运行；容器内能否访问 `host.docker.internal:11434` |
| 检索命中不到内容 | 检查知识库索引是否完成、嵌入模型是否为 BGE-M3 |
| 批改拿不到标准答案 | 检查变量赋值节点的变量名与批改节点引用是否一致 |
| 首次回答特别慢 | 模型需加载到内存，等第一次生成结束后速度会稳定 |
